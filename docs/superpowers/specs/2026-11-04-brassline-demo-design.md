# Brassline Demo 设计规格（2026-11-04）

代号 Brassline：用 Brass: Birmingham 的设定和规则做一个 Web 版 demo，验证"桌游经济外壳 + 工厂自动化内层"这个方向的流程能不能跑通。先做忠实的 Brass 数字版（热座 + 机器人，静态部署给朋友玩），流程跑通后再加实时产线内层，机制好玩再迁到中国近代工业场景。

决策已授权自主做出（用户：按建议来，不再逐项询问）。

## 1. 目标与验证问题

| 阶段 | 要回答的问题 | 完成标志 |
| --- | --- | --- |
| P0 规则引擎 | 规则是否完整、确定、可自对弈跑完整局 | 无界面模拟器跑 2/3/4 人各 200 局，全部正常终局，重放逐字节一致 |
| P1 Web 可玩版 | 人能不能在浏览器里玩完一局、看懂局面 | 自己和朋友热座或对机器人打完一局两时代，不查规则书 |
| P2 联机 | 异地朋友能不能开房间一起玩 | 服务器权威，掉线重连，两台设备打完一局 |
| P3 混合实验 | 在 Brass 的回合外壳里放实时产线，是否比纯 Brass 更有"工厂"的爽感 | 20 分钟试玩，上一篇评估的三条判定标准 |

P3 之前不碰任何混合设计，先把 P0–P1 做扎实。

## 2. 已定决策

| 项 | 决策 | 理由 |
| --- | --- | --- |
| 规则引擎 | **引入开源 MIT 引擎** `Quasrain-Coder/BrassBirmingham` 的 `packages/engine`（纯 TS、零依赖、390 个测试、三方核对过的数据表、`enumerateActions` + `applyAction` + 种子确定性重放），作为我们的 `packages/engine` 起点，保留 MIT 版权声明 | 规则保真是最大风险；一个人重写要数周且必然有漏。引擎是数据驱动的，P3 要改时在自己仓库里改 |
| 不引入的部分 | 该项目的 React 界面、服务器、LLM 机器人、官方美术素材 | 界面要换 three.js；素材是官方扫描（仅个人非商用），我们自绘 |
| 语言 / 包管理 | TypeScript 5.x，pnpm workspaces（本机 pnpm 10.23，Node 24.7） | 引擎、客户端、服务器共用类型 |
| 构建 / 测试 | Vite 8，vitest 5 | 引擎测试原样迁入 |
| 渲染 | three.js 0.187，透视相机俯视低多边形棋盘；地点是圆台，Link 是运河/铁轨段，产业板块是立方块，翻面用颜色和顶面图标表示 | 用户指定 three.js；低多边形程序生成几何，不依赖素材 |
| HUD | React 19 + DOM：手牌、行动栏、市场、收入/VP 轨、玩家面板、日志 | 文字密集的界面用 DOM 比 3D 省十倍工 |
| 状态 | 引擎状态是唯一真相；客户端只持有 `GameState` 和行动日志；zustand 做 UI 层存储 | 引擎已是纯函数，天然适合 |
| P1 部署 | 纯静态（Cloudflare Pages 或 GitHub Pages），热座 + 本地机器人，存档存 localStorage | 零服务器即可让朋友玩 |
| P2 部署 | Node `ws` 权威服务器 + SQLite 行动日志，Caddy 反代，一台 VPS | 引擎在服务端跑 `applyAction`，客户端只发行动 |
| 机器人 | P0 随机机器人跑流程；P1 贪心启发式（当前行动的即时 VP/收入收益最大者） | 验证流程不需要强 AI |
| 命名 | 项目代号 Brassline，界面里不出现 "Brass: Birmingham" 商标；地名用真实英格兰地名（事实不受版权保护） | 迁到中国场景时只换数据表和美术 |
| 美术方向 | 低多边形程序几何 + 少量 CC0 素材（Kenney / Quaternius） | 与上一篇评估一致：美术放最后 |

## 3. 规则规格（引擎验收标准）

数据来源：Roxley 官方规则书 v2018.11（`docs/reference/Brass-Birmingham-Rulebook.pdf`，文字版同目录）；版图、玩家面板、牌表、商人板块取自开源引擎 `docs/rules-reference.md`（它用官方版图扫描、玩家面板原图、TTS mod 数据三方核对）。以下是实现和验收时要逐条对照的内容。

### 3.1 组件与设置

- 2–4 人；起始 £17；收入标记在进度轨第 10 格（收入等级 0）；VP 标记在 0。
- 手牌 8 张，再抽 1 张面朝下作为弃牌堆底。
- 牌堆：4 人 64 张，3 人 54 张，2 人 40 张；Wild Location 和 Wild Industry 各 4 张单独放两叠面朝上。
- 商人板块：2 人 5 块（万能、棉、制造、空白×2），3 人加陶和空白，4 人再加棉和制造；洗混后放到可用商人位。2 人 Warrington 和 Nottingham 不放，3 人 Nottingham 不放。非空白商人板块旁放 1 桶啤酒。
- 煤市场 14 格（£1–£7 各 2 格），设置放 13 块，留 1 个 £1 格空；铁市场 10 格（£1–£5 各 2 格），放 8 块，留 2 个 £1 格空。
- 角色块洗混决定首轮顺位。
- 每时代轮数：4 人 8 轮、3 人 9 轮、2 人 10 轮（牌堆和手牌同时耗尽即时代结束）。

### 3.2 回合

- 每轮每人 2 个行动，可重复；**运河时代第 1 轮每人只 1 个行动**，铁路时代第 1 轮正常 2 个。
- 每个行动（含 Pass）弃 1 张手牌；Wild 卡弃置时放回供应堆而不是弃牌堆；行动完补手牌到 8 张。
- 花出的钱放在角色块上；轮末按本轮花费从少到多排下轮顺位，花费相同保持相对顺序；然后钱回银行，再按收入等级收钱（负收入付钱）；全局最后一轮不收收入。
- 负收入付不起：拆自己场上的产业板块，每块退成本一半向下取整，够付即停，拆掉的板块退出游戏；仍不足每缺 £1 扣 1 VP。

### 3.3 六个行动 + Pass

**Build**：唯一需要特定卡的行动。Location 卡：在该地点建任意产业，不要求在自己网络内；Industry 卡：在自己网络内建该产业（双图标卡二选一）；Wild Location 当任意 Location 卡但**不能建农场酿酒厂**；Wild Industry 当任意 Industry 卡。放该产业面板上最低级板块；优先单图标槽，其次双图标槽；运河时代每地点最多 1 块自己的板块，铁路时代不限。面板槽位带禁建图标的等级（所有 1 级，陶 1 级除外）铁路时代不可建。建煤矿放煤块（2/3/4/5），建铁厂放铁块（4/4/5/6），建酿酒厂运河时代放 1 桶、铁路时代放 2 桶。建煤矿且连通任一商人位（不要求有商人板块）时立即向煤市场卖尽量多的煤，从最贵空格起填并收钱；建铁厂无条件向铁市场卖；卖空即翻面并进收入。场上没有自己任何板块和 Link 时，可用产业卡在任意合法地点建，或用任意卡在任意空线放 Link。

**Overbuild**：用同产业更高级板块替换已放板块，照常付费。替换自己的：任意产业，板块上的资源退回供应。替换对手的：只能是煤矿或铁厂，且全版图（含市场）该种方块为 0。被替换板块退出游戏，原主人已得的收入和 VP 不收回。

**Network**：新 Link 必须与自己网络相邻（网络 = 有自己产业板块的地点 + 自己 Link 相邻的地点）。运河时代只能建运河，每次 1 条 £3。铁路时代只能建铁路，1 条 £5，或同一行动 2 条 £15 加 1 桶啤酒；每条铁路各耗 1 煤，逐条放置、逐条检查煤连通；双轨的啤酒必须来自酿酒厂，用对手酒厂时它须与第二条铁路连通。

**Develop**：从面板移除 1–2 块当前最低级板块（可不同产业），每块耗 1 铁。灯泡陶（1 级、3 级）不可 Develop。移除的板块退出游戏。

**Sell**：选自己未翻面的棉/制造/陶，须连通到印有该产业图标的商人板块（万能板块收任意）。消耗板块右上角的啤酒数；来源：自己未翻面酒厂（不需连通）、对手未翻面酒厂（须连通到用酒处）、所卖向那个商人板块旁的啤酒桶（可选，用了得商人奖励）。翻面并进收入。一次 Sell 可连续翻多块。啤酒不够则该块不能卖。

商人奖励：Gloucester 免费 Develop 1 块（不耗铁，灯泡陶除外）；Oxford 收入轨前进 2 格；Shrewsbury +4 VP；Nottingham +3 VP；Warrington +£5。

**Loan**：取 £30，收入标记后退 3 个**等级**（不是格），落在新等级最高格；不得低于 −10；不偿还。

**Scout**：弃行动卡 + 额外 2 张（共 3 张），拿 1 Wild Location + 1 Wild Industry；手里已有 Wild 不可 Scout。

**Pass**：弃 1 张卡，什么也不做。

### 3.4 资源

- **煤**：建造地点或铁路须连通煤源。优先最近的连通未翻面煤矿（任何玩家，免费，并列任选，耗尽取下一个）；没有连通煤矿才可从市场买，且须连通到 5 个商人位之一的图标；市场买空后 £8/块。
- **铁**：不需要连通。任意未翻面铁厂免费取，可混源；没有才从市场买，买空后 £6/块。
- **啤酒**：见 Sell 和 Network。
- 煤矿、铁厂、酿酒厂在最后一个资源被拿走时立即翻面（常在对手回合），主人立即进收入。棉、制造、陶只通过 Sell 翻面。
- 翻面时按板块右下数字前进收入轨的**格数**；收入等级上限 30。

### 3.5 时代末与终局

每个时代末：
1. 每条自己的 Link：两端相邻地点内，每个已翻面板块上的连接图标计 1 VP；两端是商人位的各计 2 VP。计完移除 Link。
2. 所有人移完 Link 后，自己场上已翻面产业按左下 VP 计分。未翻面不计分。

运河时代末额外：移除场上全部 1 级产业板块（面板上的不动）；补满商人啤酒；所有弃牌堆合洗成新牌堆（弃牌堆底的面朝下卡翻正）；每人重抽 8 张。

终局：两时代 VP 相加，钱和收入不折分。平局依次比收入等级、剩余现金，仍平共同获胜。

### 3.7 验收清单（引擎测试必须覆盖）

1. 铁不需要连通，煤需要；市场买煤的连通目标是商人位图标，不要求有商人板块。
2. 自己酒厂的啤酒全图可用，对手的须连通；双轨啤酒不能来自商人。
3. 时代末只移除 1 级板块；1 级陶可在铁路时代建。
4. Link 计分只数已翻面板块的连接图标，商人位固定 2。
5. 煤矿和铁厂只在建成当次卖市场。
6. 贷款退 3 个等级落在最高格，下限 −10；收入上限 30。
7. 顺位按本轮总花费。
8. 运河时代第 1 轮 1 行动。
9. Sell 一次可翻多块；商人啤酒可选，用了才给奖励。
10. 覆盖对手仅限煤/铁且全图为 0。
11. Wild Location 不能建农场酿酒厂；Wild 弃置回供应堆；有 Wild 不能 Scout。
12. 负收入拆板块半价向下取整，够付即停。
13. 酿酒厂放桶按时代（1 / 2）。
14. 终局钱和收入不折分。
15. 制造 4 级成本 £8 + 1 铁。

```
  packages/
    engine/      纯 TS 规则引擎（引入 MIT 引擎 + 我们的改动），零依赖，vitest
    sim/         无界面模拟器 CLI：自对弈、统计、重放校验（P0 完成标志）
    bots/        机器人：random（P0）、greedy（P1）
    web/         Vite + React + three.js 客户端（P1）
    server/      Node ws 权威服务器 + SQLite（P2）
  docs/
    reference/   官方规则书 PDF 与文字版
    superpowers/ specs、plans
```

边界：

- **只有 engine 结算规则**。web、server、bots 都只调用 `enumerateActions(state, player)` 和 `applyAction(state, action)`。界面的"可点位置高亮"直接来自 `enumerateActions`。
- **状态 = `GameState` + 行动日志**。存档就是 `{seed, playerCount, actions[]}`，读档即重放。P2 服务器也只存这两样。
- **three.js 只画棋盘**：地点、Link、板块、资源方块、啤酒桶、商人位。市场、轨道、手牌、面板、日志全部在 DOM。
- 棋盘几何由 `packages/web/src/board/layout.ts` 的手工坐标表驱动，迁到别的地图只换坐标和数据表。

## 5. 界面（P1）

- 相机：固定俯视约 55°，可拖拽平移、滚轮缩放；双击地点聚焦。
- 地点：圆台 + 名字标签（CSS2DRenderer），槽位是台面上的凹槽，空槽显示图标，放了板块显示立方块（玩家色侧面 + 产业图标顶面），翻面后顶面变深色并显示 VP 数字。
- Link：运河是蓝色凹槽带水面，铁路是枕木轨道；未建的线淡色虚线，可建的线在 Network 行动时高亮。
- 资源：煤矿/铁厂上堆小方块，酒厂上放桶，被取走时飞到消耗处的动画。
- HUD：顶栏（时代、轮次、顺位、当前玩家）；左侧市场（煤/铁格价）；右侧玩家面板（钱、收入、VP、板块栈）；底部手牌和行动栏；日志抽屉。
- 行动流程：选行动 → 选卡 → 在棋盘上点合法目标（来自 enumerateActions 过滤）→ 确认。Sell 和 Network 双轨支持多选后确认。
- 热座：切换玩家时遮罩手牌。机器人回合自动 1 秒一步并在日志里说明。
- 时代末：弹出计分动画（逐条 Link、逐块板块加分），运河末显示被移除的 1 级板块。

## 6. 部署

- P1：`pnpm -F web build` 产出 `dist/`，推到 Cloudflare Pages（或 GitHub Pages），分享链接即可玩；存档在 localStorage。
- P2：VPS 上 Node 进程监听 `/ws`，Caddy 做 HTTPS 和静态文件；房间 6 位码；SQLite 存 `games(seed, playerCount)`、`actions(gameId, idx, json)`；重连用 token 恢复座位。

## 8. P3 混合实验的挂点（现在不做，只预留）

- 引擎的 `applyAction` 之外增加一个 `tick(state, dt)`：每轮开始前给所有已建产业运行 N 秒实时内层，内层产出决定该板块本轮的资源数（替代固定的 2/3/4/5）。
- 地点圆台在 P3 可展开成网格厂区；P1 的圆台尺寸要给这个留余地。
- 这是唯一的接口承诺，其余等 P1 跑通后再设计。
